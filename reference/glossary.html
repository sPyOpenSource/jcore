Glossary

Canonical terms for the x86 processor modes workspace, rooted in the JCore codebase.

Processor Modes

Real Mode: The 16-bit backward-compatibility mode all x86 CPUs enter at power-on/reset. Acts like an 8086: 20-bit address bus (1 MB max), segment:offset addressing, no memory protection, no privilege levels. BIOS firmware runs here.

Protected Mode: The 32-bit operating mode introduced with the 80386. Enables 4 GB address space, hardware memory protection via segmentation and paging, 4 privilege rings (Ring 0–3), and virtual memory. JCore runs in 32-bit protected mode.

Virtual 8086 (V86) Mode: A sub-mode of protected mode that creates a virtualized real-mode environment for individual tasks. Allows a protected-mode OS to call BIOS interrupts without fully switching out of protected mode.

Long Mode: The 64-bit mode (x86-64 / AMD64). JCore does not use this yet.

Segmentation Structures

GDT (Global Descriptor Table): A table of segment descriptors shared by all tasks. Located by the GDTR register. JCore's GDT is defined in asm.S at gdt:.

Segment Descriptor: An 8-byte entry in the GDT (or LDT) that defines a memory segment's base address, limit (size), type (code/data), privilege level (DPL), and other flags (D/B, G granularity, L for long mode).

Segment Selector: A 16-bit value loaded into CS, DS, SS, ES, FS, GS. In protected mode, it's an index into the GDT (or LDT), not a raw base address. Bits 0–1 = RPL (Requested Privilege Level), bit 2 = TI (Table Indicator: GDT vs LDT), bits 3–15 = index.

GDTR: The CPU register that holds the base address and limit of the GDT. Loaded with the lgdt instruction.

Control Registers

CR0.PE (bit 0): Protection Enable. When set, the CPU is in protected mode; when clear, real mode.

CR0.PG (bit 31): Paging Enable. When set, the MMU translates linear addresses to physical addresses via page tables.

CR4.PAE (bit 5): Physical Address Extension. Required before entering long mode.

Key Instructions

lgdt: Load the GDTR register with a GDT descriptor (6 bytes: 2-byte limit + 4-byte base address).

ljmp (far jump): A jump that specifies both a segment selector and an offset. Needed after setting CR0.PE to load CS with a protected-mode selector.

DATA32 prefix: Used in 16-bit code to make the following instruction use 32-bit operands. In JCore, used in real_to_prot and prot_to_real.

JCore Codebase References

KERNEL_CS / 0x10: 32-bit protected-mode code segment selector (Ring 0). See segments.h.

KERNEL_DS / 0x18: 32-bit protected-mode data segment selector (Ring 0).

KERNEL_16_CS / 0x20: 16-bit protected-mode code segment selector. Used when switching back to real mode — the CPU must execute a 16-bit segment before clearing CR0.PE.

KERNEL_16_DS / 0x28: 16-bit protected-mode data segment selector.

real_to_prot: Assembly function in asm.S that switches from real mode → protected mode.

prot_to_real: Assembly function in asm.S that switches from protected mode → real mode.

vesa2_detect, vesa2_get_mode_info, vesa2_set_mode: Functions in asm.S that drop to real mode to call BIOS interrupt 0x10 for VESA video mode operations.

Trusted Computing Base

TCB (Trusted Computing Base): The set of all hardware, firmware, and software that must work correctly for the system's security policy to be enforced. If a component is outside the TCB, its failure cannot break security.

Reference Monitor: The conceptual component of the TCB that enforces access control — it must be tamper-proof, always invoked, and small enough to verify (the "reference validation mechanism").

Ring 0: The most privileged x86 protection ring. The kernel runs here. Code in Ring 0 can execute any CPU instruction and access any memory.

Ring 3: The least privileged x86 protection ring. User applications run here. Code in Ring 3 cannot execute privileged instructions (lgdt, mov cr0, etc.) without causing a #GP fault.

Secure Boot / Chain of Trust: Each boot stage cryptographically verifies the next before executing it. Extends the TCB concept to the boot process — the root of trust is a hardware key burned into the CPU or firmware.

Trusted Compiler Problem: If the compiler that translates source code into executable code is part of the TCB, a malicious compiler can inject backdoors without leaving traces in the source. Ken Thompson's classic "Reflections on Trusting Trust."
