Glossary

Canonical terms for the x86 processor modes workspace, rooted in the JCore codebase.

Processor Modes

Real Mode: The 16-bit backward-compatibility mode all x86 CPUs enter at power-on/reset. Acts like an 8086: 20-bit address bus (1 MB max), segment:offset addressing, no memory protection, no privilege levels. BIOS firmware runs here.

Protected Mode: The 32-bit operating mode introduced with the 80386. Enables 4 GB address space, hardware memory protection via segmentation and paging, 4 privilege rings (Ring 0–3), and virtual memory. JCore runs in 32-bit protected mode.

Virtual 8086 (V86) Mode: A sub-mode of protected mode that creates a virtualized real-mode environment for individual tasks. Allows a protected-mode OS to call BIOS interrupts without fully switching out of protected mode.

Long Mode: The 64-bit mode (x86-64 / AMD64). JCore does not use this yet.

Segmentation Structures

GDT (Global Descriptor Table): A table of segment descriptors shared by all tasks. Located by the GDTR register. JCore's GDT is defined in asm.S at gdt:.

Segment Descriptor: An 8-byte entry in the GDT (or LDT) that defines a memory segment's base address, limit (size), type (code/data), privilege level (DPL), and other flags (D/B, G granularity, L for long mode).

Segment Selector: A 16-bit value loaded into CS, DS, SS, ES, FS, GS. In protected mode, it's an index into the GDT (or LDT), not a raw base address. Bits 0–1 = RPL (Requested Privilege Level), bit 2 = TI (Table Indicator: GDT vs LDT), bits 3–15 = index.

GDTR: The CPU register that holds the base address and limit of the GDT. Loaded with the lgdt instruction.

Control Registers

CR0.PE (bit 0): Protection Enable. When set, the CPU is in protected mode; when clear, real mode.

CR0.PG (bit 31): Paging Enable. When set, the MMU translates linear addresses to physical addresses via page tables.

CR4.PAE (bit 5): Physical Address Extension. Required before entering long mode.

Key Instructions

lgdt: Load the GDTR register with a GDT descriptor (6 bytes: 2-byte limit + 4-byte base address).

ljmp (far jump): A jump that specifies both a segment selector and an offset. Needed after setting CR0.PE to load CS with a protected-mode selector.

DATA32 prefix: Used in 16-bit code to make the following instruction use 32-bit operands. In JCore, used in real_to_prot and prot_to_real.

JCore Codebase References

KERNEL_CS / 0x10: 32-bit protected-mode code segment selector (Ring 0). See segments.h.

KERNEL_DS / 0x18: 32-bit protected-mode data segment selector (Ring 0).

KERNEL_16_CS / 0x20: 16-bit protected-mode code segment selector. Used when switching back to real mode — the CPU must execute a 16-bit segment before clearing CR0.PE.

KERNEL_16_DS / 0x28: 16-bit protected-mode data segment selector.

real_to_prot: Assembly function in asm.S that switches from real mode → protected mode.

prot_to_real: Assembly function in asm.S that switches from protected mode → real mode.

vesa2_detect, vesa2_get_mode_info, vesa2_set_mode: Functions in asm.S that drop to real mode to call BIOS interrupt 0x10 for VESA video mode operations.

Trusted Computing Base

TCB (Trusted Computing Base): The set of all hardware, firmware, and software that must work correctly for the system's security policy to be enforced. If a component is outside the TCB, its failure cannot break security.

Reference Monitor: The conceptual component of the TCB that enforces access control — it must be tamper-proof, always invoked, and small enough to verify (the "reference validation mechanism").

Ring 0: The most privileged x86 protection ring. The kernel runs here. Code in Ring 0 can execute any CPU instruction and access any memory.

Ring 3: The least privileged x86 protection ring. User applications run here. Code in Ring 3 cannot execute privileged instructions (lgdt, mov cr0, etc.) without causing a #GP fault.

Secure Boot / Chain of Trust: Each boot stage cryptographically verifies the next before executing it. Extends the TCB concept to the boot process — the root of trust is a hardware key burned into the CPU or firmware.

Trusted Compiler Problem: If the compiler that translates source code into executable code is part of the TCB, a malicious compiler can inject backdoors without leaving traces in the source. Ken Thompson's classic "Reflections on Trusting Trust."

Long Mode (64-bit)

Long Mode: The 64-bit operating mode of x86-64 processors (AMD64 / Intel 64). Enables 64-bit registers (RAX–R15, RIP, RSP), 48-bit (or 57-bit) virtual addresses, and 52-bit physical addresses. Requires paging. Subsumes protected mode as the "high-performance" x86 mode.

Canonical Address: A virtual address where bits 48–63 are copies of bit 47 (sign-extended). Non-canonical addresses cause #GP. The usable range is two 47-bit regions: user space (0→0x00007FFFFFFFFFFF) and kernel space (0xFFFF800000000000→0xFFFFFFFFFFFFFFFF).

64-bit Mode: Sub-mode of long mode where code runs with 64-bit operand size by default. Entered by far-jumping to a code segment with the L (long) bit set in the GDT descriptor.

Compatibility Mode: Sub-mode of long mode where the CPU runs legacy 32-bit (or 16-bit) code. The processor is in long mode overall, but the currently executing segment is a 32-bit CS. Allows 64-bit OSes to run 32-bit applications.

EFER (Extended Feature Enable Register): MSR 0xC0000080. Controls long mode operation. Key bits: LME (bit 8, Long Mode Enable), LMA (bit 10, Long Mode Active, read-only), NXE (bit 11, No-Execute Enable).

PML4 (Page Map Level 4): The root page table in 64-bit 4-level paging. 512 entries × 8 bytes = 4 KB. Located at the physical address in CR3. Each entry points to a Page Directory Pointer Table.

PDPT (Page Directory Pointer Table): Level-2 table in 4-level paging. Entry can point to a Page Directory (4 KB pages) or directly to a 1 GB page (PS=1).

LA57: 5-level paging (CR4.LA57=1). Adds a third level above PML4, increasing virtual address space to 57-bit (128 PB). Supported on Ice Lake and later Intel CPUs, Zen 2 and later AMD.

NX (No-Execute) Bit: Bit 63 in 64-bit page table entries. When set, the page cannot be executed as code. Requires EFER.NXE=1. The hardware basis for W^X (write XOR execute) policies.

RIP-Relative Addressing: An addressing mode in 64-bit mode where the effective address is computed relative to RIP (the instruction pointer). Enables position-independent code (PIC) without the overhead of a base register.

Memory Management Unit

MMU (Memory Management Unit): Hardware in the CPU that translates every virtual address to a physical address. On x86, enabled by CR0.PG bit. Consists of page table walker + TLB cache.

Virtual Address: The address a program sees. Translated by the MMU to a physical address before reaching the memory bus.

Physical Address: The actual address sent to RAM. Invisible to user programs.

Page: A fixed-size block of virtual memory, aligned to its size. x86 supports 4 KB, 2 MB, and 1 GB pages (32-bit: 4 KB and 4 MB).

Page Frame: A fixed-size block of physical memory. A page maps to a page frame of the same size.

Page Directory (PD): Level-1 table in 32-bit paging. 1024 entries × 4 bytes = 4 KB. Located at the address in CR3. Each entry points to a page table (or a 4 MB page if PS=1).

Page Table (PT): Level-2 table in 32-bit paging. 1024 entries × 4 bytes = 4 KB. Each entry points to a 4 KB page frame.

CR3: Control register holding the physical address of the root page table (page directory on 32-bit, PML4 on x86-64). Also called PDBR (Page Directory Base Register).

TLB (Translation Lookaside Buffer): On-chip cache of recent virtual→physical translations. Acts as the CPU's "MMU cache." Must be invalidated when page tables change (invlpg instruction or CR3 reload).

Page Fault (#PF): Exception (interrupt 14) raised when the MMU cannot translate a virtual address — either the page is not present, or a protection violation occurred. The faulting address is stored in CR2. JCore's handler is in exception.S.

Page Table Walk: The process of traversing page directory/table entries to find a translation. On x86, the hardware performs the walk automatically on a TLB miss.

Triple Fault: When the CPU encounters a fault while trying to deliver a double fault, it shuts down and resets. Commonly caused by disabling paging without identity-mapping the code page — the CPU can't fetch the next instruction and faults repeatedly until reset.

Identity Mapping: A page table setup where virtual address X maps to physical address X (1:1). Required during paging transitions — the code that clears or sets CR0.PG must be identity-mapped so the CPU can still fetch instructions after the MMU changes state.
