ARMv7-A Context Switch Reference

Registers, exceptions, and the PendSV pattern

ARMv7-A Register Set

General-purpose:
  r0–r3    Caller-saved (scratch)
  r4–r11   Callee-saved (must preserve across context switch)
  r12      Intra-procedure-call scratch (IP)
  r13 (SP) Stack pointer (banked per mode)
  r14 (LR) Link register (banked per mode)
  r15 (PC) Program counter

Status:
  CPSR      Current Program Status Register
  SPSR_<mode>  Saved PSR (banked per exception mode)
Context switch minimum save: r4–r11, SP, LR. The compiler saves r0–r3 and r12 on function entry (AAPCS). PC is implicit — you return to it by restoring LR into PC.

The PendSV Pattern

PendSV (SuperVisor call Pend-ing, exception 14, vector offset 0x38) is the standard ARM mechanism for deferred context switching.

Why it exists

If you context-switch inside the SysTick handler directly, the ISR saves the interrupted task's state on the interrupt stack (SP_irq or SP_svc). But IRQ handlers use banked SP — the stacked state is mixed with interrupt return addresses. PendSV lets you:

  1. Do minimal work in SysTick (just set a flag / increment a counter)
  2. Pend PendSV by writing bit 28 of ICSR (0xE000ED04)
  3. Return from SysTick — CPU goes back to the interrupted task
  4. PendSV fires immediately after if no other exceptions are pending, running in SVC mode with SP_svc

Sequence diagram

SysTick fires
  → Save r0–r3, r12, LR, PC, xPSR automatically (ARMv7-A pushes these on exception entry)
  → Enter handler mode
  → Pend PendSV (write ICSR[28] = 1)
  → Return from exception (BX LR with EXC_RETURN)
  → (optional: higher-priority IRQ runs here)
  → PendSV fires in SVC mode
  → Save r4–r11 of current task onto its stack
  → Switch SP to next task's stack
  → Restore r4–r11 of next task
  → Return from exception → next task runs

ICSR register

ICSR (0xE000ED04):
  Bit 28: PENDSVSET — write 1 to pend PendSV
  Bit 27: PENDSVCLR — write 1 to unpend

Minimal PendSV Handler

.globl PendSV_Handler
PendSV_Handler:
    # Save callee-saved registers of current task
    # (r0–r3, r12, LR, PC, xPSR already saved by hardware)
    mrs     r0, psp              # Get PSP (process stack pointer)
    stmdb   r0!, {r4-r11}        # Save r4–r11 onto task stack
    ldr     r1, =current_tcb
    str     r0, [r1]             # Save updated SP to TCB

    # Switch to next task
    bl      scheduler_next       # Returns next TCB pointer in r0
    ldr     r1, =current_tcb
    str     r0, [r1]             # Update current_tcb
    ldr     r0, [r0]             # Load SP from TCB

    # Restore callee-saved registers of next task
    ldmia   r0!, {r4-r11}        # Restore r4–r11
    msr     psp, r0              # Restore PSP

    # Return to next task
    bx      lr                   # (LR contains EXC_RETURN)
PSP vs MSP: Cortex-A15 has two stack pointers: MSP (main, used in handler mode) and PSP (process, used in thread mode). Tasks run in thread mode using PSP. The kernel runs in handler mode using MSP. This separation is why PendSV can save the task's SP without clobbering the kernel's stack.
