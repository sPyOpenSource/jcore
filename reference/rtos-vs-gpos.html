RTOS vs General-Purpose OS

Core Distinction

DimensionRTOSGeneral-Purpose OS (Linux, Windows)
Goal Meet deadlines — worst-case latency matters Maximize throughput — average-case matters
Scheduler Priority-based preemptive, fixed priority Fair-share (CFS), O(1), or round-robin with dynamic priority
Dispatch latency Deterministic, bounded (microseconds) Variable (milliseconds to seconds under load)
Kernel preemption Fully preemptible (short critical sections) PREEMPT_RT needed for near-rt; standard kernel has long preempt-off regions
Memory model Static allocation preferred, no page faults in ISRs Virtual memory, demand paging, overcommit, swap
Protection Often trust-based (everything privileged) or lightweight domains Full user/kernel MMU separation, isolated process address spaces
IPC Message queues, semaphores, mutexes with priority inheritance Pipes, sockets, shared memory, signals, D-Bus
Priority inversion Handled by protocol (priority inheritance, ceiling) Not guaranteed — can cause unbounded priority inversion on standard kernel
Blocking Minimized — spin on hardware registers, no kernel blocking in ISRs Kernel can block (page faults, I/O wait, sleep)
Timers Tick-driven or tickless, one-shot timers common Multi-tick, high-resolution timers optional (hrtimers)
Typical scale KB–MB of RAM, no storage required MB–GB of RAM, filesystem required
Examples FreeRTOS, Zephyr, RT-Thread, VxWorks, µC/OS Linux, Windows, macOS, FreeBSD

Priority Inversion in One Diagram

Without priority inheritance:
  Low-pri task holds mutex M
  ─> High-pri task tries to lock M — BLOCKED
  ─> Medium-pri task preempts Low (no relation to M)
  ─> High-pri stays blocked until Medium yields
  ─> Bounded → unbounded delay for High

With priority inheritance:
  Low-pri task holds mutex M
  ─> High-pri tries to lock M — BLOCKED
  ─> Low inherits High's priority (temporarily)
  ─> Low finishes critical section, releases M
  ─> Low's priority drops back, High runs

Where Your RTOS Fits

The RTOS you're building on the BBAI:

  • Trust-based — everything in SVC mode, no user/kernel split
  • Domain isolation — task stacks in separate CLIENT domains
  • Deterministic context switch — PendSV + fixed priorities
  • Static allocation — task stacks and TCBs allocated at build time
  • No filesystem, no networking — pure compute + UART + GPIO for now

This is a deliberately minimal RTOS — closer to FreeRTOS than to Linux. The hardware (Cortex-A15) is far more powerful than what most RTOSs run on, but the software model is the same.
