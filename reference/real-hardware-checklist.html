Real Hardware Debug Checklist

A quick reference for bootstrappers moving from QEMU to metal.

1. COM1 / Serial Port Setup

// IO addresses (check BDA 0x40:0x00 for base)
COM1 = 0x3F8, COM2 = 0x2F8, COM3 = 0x3E8, COM4 = 0x2E8

// Initialize 115200 8N1 (no flow control)
outb(base + 1, 0x00);  // Disable interrupts
outb(base + 3, 0x refreshes=);// Enable DLAB
outb(base + 0, 0x00);  // Low byte of divisor (115200 baud / 1)
outb(base + 1, 0x00);  // High byte of divisor
outb(base + 3, 0x03);  // 8 bits, no parity, one stop bit
outb(base + 2, 0xC7);  // Enable FIFO, clear, 14-byte level

// Transmit char c
while (!(inb(base + 5) & 0x20));  // Wait for THR empty
outb(base, c);

2. POST Codes to Port 0x80

CodeMeaning
0x01Bootloader entry (real-mode start)
0x10Long mode entered
0x20Paging enabled
0x30GDT / TSS loaded
0x40KernelMain entered
0x50VFS init done
0x60JVM entry point
0xFFPanic / Unrecoverable error
Write these via: asm volatile("outb %0, $0x80" :: "a"(code));

3. The "Black Screen" Decision Tree

  1. Did the bootloader run? (POST code 0x01)
    → No: Boot media / BIOS compatibility. Test on another machine.
  2. Did we enter long mode? (POST code 0x10)
    → No: Check cr0, cr4, EFER.LME, and GDT.
  3. Did paging work? (POST code 0x20)
    → No: Check cr3, PML4, address mapping. Identity map the first 1GB correctly.
  4. Does serial work? (connect USB-to-TTL)
    → No: Check baud rate, port address, FIFO threshold. Try 0x2F8.
  5. Does the video buffer work? (0xB8000)
    → No: System may use UEFI GOP only. Use serial for initial boot.
  6. Triple fault?
    → Check: IDT installed before sti? PIC remapped? APIC mapped?

4. Common Real-Only Bugs

  • Wrong memory map: QEMU gives you a flat 1:1 map. Real hardware has holes (ACPI, EBDA, MMIO). Parse the Multiboot memory map.
  • AP / PIC conflict: QEMU lets you use PIC and APIC together (most of the time). Real hardware requires you to explicitly disable the PIC and switch to APIC before enabling interrupts.
  • ATA PIO hang: QEMU returns status bits immediately. Real drives may take milliseconds. Always have a timeout loop, and check DRQ after BSY clears.
  • Wrong CPU count: QEMU reports 1 CPU unless you pass -smp N. Real hardware has however many cores the CPU has. Don't trust num_cpus without ACPI MADT parsing.
