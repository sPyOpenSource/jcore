GC Glossary

Canonical terms for the JVM garbage-collection thread of lessons, rooted in the JCore codebase (src/Memory/gc_*.c).

Core model

Garbage: An object that is unreachable from the root set. Reachability — not any program action — defines what the collector may reclaim.

Root set: The objects a collector starts tracing from: active thread stacks (local variables, operand stack), static fields of loaded classes, JNI references, and JIT-held registers. JCore scans these in gc_org_gc() (gc_org.c:1084).

Reachability levels (defined by java.lang.ref): strong (plain references), soft (SoftReference — reclaimed only under memory pressure), weak (WeakReference — reclaimed at the next GC), phantom (PhantomReference — reclaimed and enqueued for post-mortem cleanup).

Mutator: The application threads that allocate objects and mutate the object graph — everything that is not the collector.

Algorithm families

Reference counting: Each object tracks the number of incoming references; count hits zero ⇒ free immediately. Simple, incremental, but leaks cycles and needs per-store overhead. Not used by HotSpot.

Tracing collection: Traverse the object graph from the roots; everything not visited is garbage. The family every HotSpot collector belongs to.

Mark-sweep: Tracing that marks reachable objects, then sweeps the heap freeing unmarked ones. Leaves fragmentation.

Copying collection (semispace): Tracively copy survivors from from-space into an empty to-space; the whole old space is then garbage. Allocation is a bump pointer; survivors get relocated (cheap allocation, fast collection, but only half the heap usable at once). JCore's default gc_org.c is this design (heaps heap and heap2). Cheney's algorithm is the classic breadth-first variant.

Mark-compact: Mark reachable objects, then slide them together to one end, eliminating fragmentation. Used in HotSpot's Serial Old.

Generational collection: The empirical weak generational hypothesis — most objects die young — splits the heap into a young generation (collected frequently, cheaply) and an old generation (collected rarely). Young GCs are usually copying; old GCs mark-sweep/compact. Basis of HotSpot (Eden + Survivors + Tenured).

Incremental / concurrent / parallel / stop-the-world: Parallel = multiple GC threads; stop-the-world = all mutators paused; concurrent = collector runs at the same time as mutators (CMS, G1, ZGC, Shenandoah); incremental = collection work spread over time.

JCore codebase references

gc_org.c: The original copying (semispace) collector. gc_org_gc() at line 1084 is the entry point; gc_org_allocHeap2() at line 62 is the to-space bump pointer.

gc_compacting.c: Mark-compact implementation (HotSpot Old-gen analogue).

gc_bitmap.c: Bitmap-based collector — reuses the bitmap idea from jxmalloc, applied to liveness marking.

gc_chunked.c: Region/chunk-based collector (conceptual ancestor of G1's regions).

gc_stack.c: Stack scanning — which words on a thread stack are roots (uses stack maps).

gc_pa.c: Parallel allocation / GC support code.

gc_alloc.c: Object allocation path (gc_allocDataInDomain), the mutator-facing front door of the heap.

OBJSIZE_* / OBJFLAGS_* (gc.h): JCore stores per-object metadata (flags, vtable, size) in words preceding the object header — the collector's way of knowing an object's layout.

JVM heap terms (HotSpot)

Young generation: Eden + two Survivor spaces. New objects land in Eden (bump allocation); survivors age by being copied Survivor0 → Survivor1.

Old generation (Tenured): Long-lived survivors are promoted here; collected by mark-sweep/compact (or G1's mixed collections).

Minor vs major/full GC: Minor collects only the young gen; full collects the whole heap. A promotion failure (no room in old gen) can force a full GC.

Safepoint: A point where all mutators are frozen so the collector can identify roots (stacks, registers) consistently. JCore triggers collection only when it can safely inspect threads.

Card table / remembered set: The young-gen collector must know which old-gen objects reference young objects (cross-generation pointers); a card table is a coarse bitmap of dirty old-gen pages, a remembered set the refined structure.
