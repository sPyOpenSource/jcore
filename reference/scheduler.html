Two-level runqueue

domain_runqueue            global FIFO of runnable domains   (runq.c:25)
   └── domain->firstThreadInRunQueue  per-domain FIFO of threads
  • Pick: runqueue_removeFirstOrNULL() (runq.c:301) — head domain, then head thread; current domain appended if still runnable.
  • Invariant: only STATE_RUNNABLE threads are queued; ASSERTed before every switch.
  • Queued-ness stored in domain->sched.untypedGlobalMemory (NEW_SCHED) / nextInRunQueue links — no heap calls in the hot path.

The switch (switch.S)

  • internal_switch_to — save current thread's EIP/ESP/EBP/ESI/EDI/EFLAGS into its context[], then restore the next thread's and ret into it. Thread resumes mid-instruction.
  • destroy_switch_to — restore next thread without saving current (current is dying).

LLS / HLS split (JAVASCHEDULER mode)

In Java-scheduler mode both levels can be Java objects in the heap — which is why the GC must move scheduler objects.

LevelRoleGrounding
LLS (Low-Level)per-CPU: domain switching, time slices, IRQ handling. Java class jx/zero/LowLevelScheduler, method pointers resolved via vtable in LLSched_register().javascheduler.c:532
HLS (High-Level)per-domain per-CPU: thread-level policy. Java class jx/zero/scheduler/HighLevelScheduler, callbacks preempted/interrupted/activated.javascheduler.c:588

GC interplay: gc_org_moveSchedulerObject() (gc_org.c:48) relocates each CPU's HLS object after a copying collection; gc_impl.c:43 walkSchedulerObjects() iterates the same table.

Idle thread

for(;;){ sti; hlt; cli; while(domain_runqueue.first==NULL); threadyield(); }

Parks the CPU on hlt until an interrupt (timer/device/IPI) wakes it to re-check the runqueue.
