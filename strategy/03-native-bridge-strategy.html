Strategy 3: Native Bridge Implementation

The task breakdown: how to implement your Native Interface in FlintJVM and link it to the Raspberry Pi.

The Native Bridge is the layer that connects FlintJVM to the host hardware. The FlintJVM core knows nothing about Raspberry Pi peripherals; it only knows about an abstract interface.

Core Insight: Two-Step Process

  1. Implement FlintJVM's Virtual Interface: We need to create a concrete class that inherits from FlintJVM's NativeInterface and implements all virtual functions.
  2. Implement the Native Functions: Fill in the actual logic for things like native_uart_putc that writes to RPi's memory.

The two steps are distinct. Implementing the first is simply a matter of filling in function signatures. The second is where we write our own code.

Understanding the Native Interface Structure

The FlintJVM Native Interface (addon/FlintJVM/Native/Inc/flint_native_interface.h) is a class full of pure virtual functions. Each one represents a method call you would make from Java code.

Here is a minimal set of functions you should implement first (to get System.out.println() working):

  • virtual jint native_system_get_time(); - Typically used by Java's System.currentTimeMillis()
  • virtual void native_uart_putc(uint8_t c); - Writes a character to the RPi UART register (0xFE201000 + data register offset)
  • virtual void native_pin_set(uint8_t pin, uint8_t value); - Controls GPIO (for LED blinking in hello)
Strategy: Start with these 3 functions. You can wrap them in a class called RpiNativeBridge.

File Organization Options

PatternProsCons
One rpithal.cpp file Simpler to compile, all natives in one place. Difficult to maintain, mixing UART + filesystem + networking concerns.
Multiple *_native.cpp files Easier to organize, easier to unit test, separates concerns by hardware type. More build files to manage, more complex build dependency graph.

Implementation Algorithm

Your overall plan should be something like this:

  1. Header File Creation:
    • Create a new header addon/FlintJVM/Native/Inc/rpithal_interface.h
    • Define your RpiNativeBridge class that inherits from FlintJVM's native interface
    • Add pure virtual functions for everything you need
  2. Implementation File Creation:
    • Create rpithal.cpp in the same directory or in a separate addon/FlintJVM/Native/RPI subdirectory
    • Implement every virtual function you declared
    • For physical hardware interaction, call RPi-specific functions (from src drivers)
  3. addon/FlintJVM/Native/Makefile:
    • Add your rpithal.cpp file to the OBJS list
    • Ensure it builds into libwvm.a
  4. Update the FlintJVM core to use your class:
    • You may need to modify addon/FlintJVM/Native/flint_native.cpp or src/addon/rosina.cpp to instantiate your concrete class
    • There should be a platform-specific newNativeBridge() function somewhere

Specific Implementation: uart_putc Example

Here's a minimal example of your native_uart_putc() implementation in C++:

#include "Native/Inc/rpithal_interface.h"
#include "/src/drivers/uart.h" // Or however Circle's UART is exposed

class RpiNativeBridge : public NativeInterface {
public:
    // ... other virtual functions...
    
    void native_uart_putc(uint8_t c) override {
        // RPi UART0 registers
        // Base address: 0xFE201000
        // Data register offset: 0x00
        const volatile uint32_t *uart_dr = (uint32_t*)0xFE201000;
        
        // Wait until line is empty (bit 5 of FR not set)
        while ((*uart_dr & (1 << 5)) != 0);
        
        // Write character
        *uart_dr = c & 0xFF;
    }
    
    // ... other implementations
};

Implementation of the static initialization should be handled similarly to how ESP32 does it in the FlintJVM native interface.

The RPi HAL Layer

The division of work for RPi HAL is similar to other platforms:

  • The JVM knows nothing about hardware
  • One layer: Platform Independent Native Interface (NPI = FlintJVM Native Interface)
  • One layer: Platform Specific Native HAL (RpiNativeBridge)

Building the FlintJVM Library

The FlintJVM core is built as libwvm.a. This library must be compiled and linked with Circle's kernel.

The build of FlintJVM is handled in addon/FlintJVM/Makefile

You need to make sure your native implementation is included, and that libwvm.a includes your code.

Phase 4: Compiling for Raspberry Pi and Flint Integration

Now that we have the Native HAL implemented, we need to make sure it compiles and links with the Circle kernel.

  • Update FlintJVM's addon/FlintJVM/Native/Makefile to include your new addon/FlintJVM/Native/rpithal.cpp file.
  • Modify sample/44-ESPJVM/Makefile to reference the addon/FlintJVM/libwvm.a (which now contains your RPi HAL).
  • Change compile flags in FlintJVM if needed (e.g., -march=armv8-a, -mtune=cortex-a72)
