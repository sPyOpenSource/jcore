Lesson 3: Native Implementation Walkthrough

Making the FlintJVM work on your hardware is a two-step process: implement the JVM core and the Native HAL.

Step 1: Implement the Native Interface in FlintJVM

Look at the addon/FlintJVM/Native/flint_native_interface.cpp file. This is the core of the Native Bridge — a C++ header file that provides a uniform interface for the JVM core to call host functions. This file contains a set of pure virtual functions that every platform (FlintJVM has ESP32, RPi, PC, etc.) must implement.

This file is important because it tells you exactly what functions you must write. These are not implemented in ESP32 (or any other platform) as-is — you will implement them specifically for RPi.

Your New Job: Implement the Native Interface for RPi. This is what connects FlintJVM to the Raspberry Pi.

Step 2: Choose Your Implementation Location

There are two ways to implement the Native Interface:

  • One large file: Everything in a single rpithal.cpp (Easier to compile, Harder to organize)
  • One file per interface: One native_*.cpp per RPi peripheral (Easier to organize, Harder to compile)
Requirement: You must implement a minimal set of native functions to get a "Hello World" working. Based on FlintJVM's architecture and what we've seen in the JAM Clojure example, you need at least system_get_time, uart_putc, and possibly pin_set to make System.out.println("Hello") work.

What's the Function Signature Format?

The function signatures in flint_native_interface.h look like this:

virtual JNMPtr GetJavaClass(const char *name) = 0; // Summary: Looks up a Java class
virtual jint NativeMethodWrapper(JavaClass *obj, MethodInfo *methodInfo, JNMPtr methodPtr, JNMPtr thisPtr, va_list args); // Summary: Entry point for native method

Implementing these is the EASY part of porting FlintJVM to RPi. The HARD part is writing the native function implementations that follow them — things like your own uart_putc that writes to RPi's peripheral register at 0xFE201000.

The Native Interface Hierarchy (for ESP32 it's straightforward)

Let's look at the structure of the same system for the ESP32 (which we can infer exists because FlintJVM works on ESP32). The ESP32 has a set of native function wrappers like NativeFile(), NativeConsole(). This is the same for RPi.

When FlintJVM calls a native function like System.out.println, it goes:

  • JVM Core → Native Bridge NativeMethodWrapper → Friend in C++ (NativeNative.cxx) → {Your function}

The "Good Enough" Approach (What You Should Do First)

Since we are on a strict timeline, and this is a learning-oriented course, implement a minimal set of native functions and debug them. Look for existing implementations of RPi's native functions in the src/drivers or addon/native directories.

Once you have basic native functions working, you can progressively add full functionality (like Thread, File, System) as the JVM core calls them.

Step 3: Fix the FlintJVM & Makefile

You'll have to fix the FlintJVM Makefile so the Native Interface gets compiled into libwvm.a. You'll need to:

  1. Create an rpithal.cpp (or a directory of native files) that implements FlintJVM's Native Interface.
  2. Add your implementation(s) to the FlintJVM Makefile (which builds libwvm.a — FlintJVM's core library).
  3. Modify the Makefile in sample/44-ESPJVM to point to the updated libwvm.a from addon/FlintJVM so Circle can link correctly.

Step 4: Compile an RPi Kernel with FlintJVM

After we have a working native layer for RPi, you can try to compile the Circle kernel with the FlintJVM installed. The same steps as before to build the Circle kernel — you can now reference the native layer you built in building Circle.
