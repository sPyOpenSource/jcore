Lesson 0002

Symmetric Multiprocessing: From One Core to Many

Your current x86OS kernel runs on a single CPU core. The TaskManager schedules tasks, the InterruptManager handles IRQs, and the MemoryManager manages physical frames — all assuming one stream of execution. SMP breaks that assumption. This lesson covers what changes when you add a second, fourth, or sixty-fourth core.

1. What Changes in SMP?

In a uniprocessor kernel, "current task" is a global variable. In SMP, every core runs its own task simultaneously. The kernel must become re-entrant and concurrent at every level.

SMP (Symmetric Multiprocessing): Multiple identical CPU cores sharing the same memory bus, I/O bus, and interrupt controller. Any core can run any task or handle any interrupt.
APIC (Advanced Programmable Interrupt Controller): The modern replacement for the PIC. Each core has a Local APIC; the I/O APIC routes device interrupts to specific cores.

Key areas that must change:

  • Scheduler: Per-CPU runqueues, load balancing, task affinity.
  • Interrupts: Per-core IDT, IPI (Inter-Processor Interrupts) for cross-core signaling.
  • Memory: Per-CPU allocator caches, TLB shootdowns for page table changes.
  • Synchronization: Spinlocks (with IRQ disable), RCU, per-CPU variables.
  • Timekeeping: Per-core timer (LAPIC timer), synchronized TSC.

The AP starts in 16-bit real mode at the SIPI vector. The trampoline code (typically placed at 0x8000 or similar) must:

  1. Switch to protected mode
  2. Enable PAE and long mode
  3. Load per-CPU GDT (with TSS for kernel stack)
  4. Jump to ap_main() in C
Your current kernel: kernel.cpp constructs InterruptManager and TaskManager as singletons. For SMP, these become per-CPU structures. The BSP initializes the global structures; each AP initializes its own local copies.

4. Scheduler Changes for SMP

Your current TaskManager::Schedule() is a simple round-robin over a global array. In SMP, each CPU has its own runqueue. The scheduler runs on each core independently via the timer interrupt.

Load balancing happens periodically (or when a runqueue is empty): steal tasks from the busiest CPU's runqueue.

Your current TaskManager uses a simple array and currentTask index. For SMP, replace with per-CPU Runqueue and add spinlock_t for concurrent access during task migration.

5. Inter-Processor Interrupts (IPIs)

IPIs are the primary communication mechanism between cores. Common IPI types:

IPI TypeVectorPurpose
Reschedule0xF0Force target CPU to reschedule (task woke up)
TLB Shootdown0xF1Invalidate TLB entries after page table change
Generic Function0xF2Run arbitrary function on target CPU
Timer Sync0xF3Synchronize TSC / LAPIC timers
Shutdown0xF4Halt target CPU

6. Synchronization Primitives

Your kernel currently runs with interrupts disabled (cli) in critical sections. In SMP, cli only masks interrupts on the local CPU. You need spinlocks.

Use this to protect per-CPU runqueues, global resource lists, and any data shared across cores.

Key rule: Never block (sleep/wait) while holding a spinlock. Spinlocks are only for short, non-blocking critical sections. For longer waits, use mutexes/semaphores that can sleep — but those require a working scheduler first.

7. TLB Shootdowns

When CPU 0 modifies a page table (e.g., mmap, munmap, page fault handling), other CPUs may have stale TLB entries. You must invalidate them via IPI.

8. Integration with Your x86OS

Here's a minimal roadmap to add SMP to your existing kernel:

  1. ACPI Parsing: Parse MADT (Multiple APIC Description Table) to get CPU count, APIC IDs, I/O APIC info.
  2. Per-CPU GDT/TSS: Allocate one GDT and TSS per CPU. The TSS holds the kernel stack pointer (RSP0) for each CPU.
  3. Trampoline Code: Write 16-bit assembly (place at 0x8000) that APs execute on SIPI.
  4. Local APIC Driver: Map LAPIC MMIO, implement timer (for scheduler tick), IPI send/recv, EOI.
  5. Per-CPU Storage: Allocate CpuLocal array, set up GS base via wrgsbase (or swapgs + MSR).
  6. Initialize APs: BSP runs INIT-SIPI-SIPI, each AP calls ap_main() → initializes local IDT, LAPIC timer, enables interrupts.
  7. Scheduler: Convert global TaskManager to per-CPU Runqueue with spinlocks.
  8. Locking: Replace all cli/sti critical sections with spinlocks.
