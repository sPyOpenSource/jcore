Long Mode — The 64-bit World

Lesson 4 of the x86 Processor Modes series.

1. What Long Mode Adds

Long mode is the 64-bit operating mode introduced by AMD with the Athlon 64 (2003) and later adopted by Intel as EM64T / Intel 64. It's not "protected mode with bigger registers" — it's a fundamental redesign of how the CPU operates.

Protected Mode (32-bit)Long Mode (64-bit)
General registers8 (EAX–EDI)16 (RAX–R15)
Register width32 bits64 bits
Virtual address space4 GB256 TB (48-bit)
Physical address space64 GB (PAE) / 4 GB (no PAE)1 TB – 4 PB (implementation-dependent)
SegmentationFull segment:offset modelMostly flat (CS/DS/ES/SS base forced to 0)
Paging required?OptionalMandatory
Page table levels2 (PD + PT) or 3 with PAE4 (PML4 + PDPT + PD + PT) or 5 with LA57
Hardware task switchingSupported (TSS)Removed
V86 modeSupportedRemoved

2. Segmentation Changes

In long mode, segment registers work differently:

  • CS, DS, ES, SS: base and limit are ignored — they're treated as 0 and unlimited. The only meaningful fields are DPL (privilege level) and the L bit (64-bit code vs compatibility mode).
  • FS and GS: base addresses still work (set via MSRs 0xC0000100 and 0xC0000101). These are used for thread-local storage (FS on Linux, GS on Windows) and per-CPU data.

Compare with JCore's GDT (segments.h), which has separate 32-bit and 16-bit segments for mode switching. In long mode, the 16-bit segments would have no special meaning — you'd need completely different GDT entries with the L bit set.

3. Four-Level Paging

Long mode uses 4-level page tables (5-level with LA57 on newer CPUs). Each level has 512 entries × 8 bytes = 4 KB per table:

Virtual address (48-bit canonical):
┌──────┬──────┬──────┬──────┬──────────┐
│ PML4 │ PDPT │  PD  │  PT  │  offset  │
│ 9bit │ 9bit │ 9bit │ 9bit │  12bit   │
└──────┴──────┴──────┴──────┴──────────┘
   ↓      ↓      ↓      ↓
  CR3 → PML4 → PDPT → PD → PT → 4 KB page

Each 64-bit PTE has the same permission bits as 32-bit (Present, R/W, U/S, A, D, etc.) plus new ones:

  • NX (bit 63): No-Execute — marks a page as non-executable. Enabled via EFER.NXE. This is the hardware basis for W^X (write XOR execute) security policy.
  • PAT (bit 7): Page Attribute Table — for fine-grained memory type control.

Because PTE entries are 8 bytes and each table is 4 KB, you get 512 entries per level. The total coverage: 5124 × 4 KB = 256 TB (48-bit virtual address space).

4. Canonical Addresses

A 64-bit pointer in long mode must be canonical: bits 48–63 must be a copy of bit 47 (sign-extension). This splits the virtual address space into two regions:

0x0000_0000_0000_0000  ┌────────────────────┐
                       │  User space (47-bit)│
0x0000_7FFF_FFFF_FFFF  ├────────────────────┤
0xFFFF_8000_0000_0000  │  Kernel space (47-bit)│
                       └────────────────────┘
0xFFFF_FFFF_FFFF_FFFF

Non-canonical addresses (e.g., 0x0000_8000_0000_0000) cause a #GP fault if accessed. This is why 64-bit OSes can't use a full 64-bit address space — the unused high bits must be copies of bit 47.

5. Entering Long Mode

From protected mode, the sequence is:

1. Disable interrupts (CLI)
2. Enable PAE (CR4.PAE = 1)
3. Set up 4-level page tables with PML4 at CR3
4. Set EFER.LME = 1 (WRMSR 0xC0000080)
5. Enable paging (CR0.PG = 1) — this atomically enters long mode,
   EFER.LMA becomes 1
6. Far jump to a 64-bit code segment (GDT entry with L=1)
   → CPU is now in 64-bit mode

Step 5 is the key moment: setting CR0.PG with EFER.LME=1 transitions from protected mode to compatibility mode (still 32-bit instructions). Step 6 switches to true 64-bit mode.

6. Long Mode and JCore's Future

Your learning record 0003-32bit-vs-64bit already identifies what would change for a 64-bit port:

  • BCBasicDatatype.REFERENCE → return 8 (not 4)
  • BCReference.value → long (not int)
  • addr_t → unsigned long long
  • 8-byte alignment for objects
  • AArch64 assembly (currently x86-only)

For x86-64 specifically, JCore would need:

  • A new GDT with 64-bit code segments (L=1 in the descriptor)
  • The 4-level paging structures (PML4 → PDPT → PD → PT)
  • NX-bit support in page table entries for W^X policy
  • Rewrite all inline assembly (lowlevel.S, asm.S) for 64-bit operands
  • Replace the prot_to_real / real_to_prot mechanism — real mode switching is architecturally different from long mode
Key insight: Long mode removes V86 mode and hardware task switching. If JCore ever goes 64-bit, the BIOS interrupt calls (VESA video modes, ACPI) that currently use prot_to_real would need a completely different approach — either a UEFI GOP framebuffer, or a trampoline that drops through compatibility mode to real mode.
