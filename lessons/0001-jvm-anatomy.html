Lesson 1: The Anatomy of a JVM

Deconstructing the virtual machine into implementable components.

To implement a JVM on bare metal, we must first stop thinking of it as "software" and start thinking of it as a virtual CPU. A JVM is essentially a software-defined processor that executes a specific instruction set (bytecode) instead of native ARM instructions.

The Three Pillars of the JVM

According to the JVM Specification, the machine consists of three primary subsystems:

ComponentResponsibilityBare-Metal Challenge
Class LoaderReads .class files and transforms them into internal runtime structures.Reading from SD card / Flash using Circle's filesystem drivers.
Runtime Data AreasThe memory "state" of the machine (Heap, Stack, Program Counter).Allocating large contiguous blocks of RAM and managing them without an OS.
Execution EngineThe "CPU" that reads bytecode and produces actions (Interpreter or JIT).Efficiently mapping bytecode to AArch64 instructions.

The Runtime Data Areas (The Memory Map)

This is the most critical part of your implementation. You aren't just allocating memory; you are designing a memory architecture. You will need to implement:

  • The Program Counter (PC): A pointer to the current bytecode instruction being executed.
  • The JVM Stack: A LIFO structure for method frames. Each frame contains local variables and an operand stack (where calculations happen).
  • The Heap: The shared area where all Java objects live. This is where your Garbage Collector will operate.
  • The Method Area: Where class structures (metadata) are stored.
The "Stack-Based" Secret: Unlike the ARM CPU, which uses registers (x0, x1, etc.), the JVM is a stack-based machine. To add two numbers, it doesn't do add x0, x1, x2; it pushes two numbers onto the operand stack, calls iadd, and the result is pushed back.

The Execution Loop

At its simplest level, your JVM implementation will be a giant while loop that looks like this:

while (running) {
    uint8_t opcode = fetch_next_bytecode();
    switch (opcode) {
        case OP_IADD: // Integer Add
            int a = pop();
            int b = pop();
            push(a + b);
            break;
        case OP_INVOKEVIRTUAL:
            handle_method_call();
            break;
        // ... hundreds of other opcodes
    }
}
