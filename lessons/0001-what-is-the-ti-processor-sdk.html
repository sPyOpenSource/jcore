What is the TI Processor SDK?

Navigating TI's software ecosystem for the AM5729

Goal

After this lesson, you'll be able to look at any TI-provided file or tool for the AM57x and know what it is, where it lives in the SDK, and whether it's useful for baremetal OS work on the BeagleBone AI.

The Core Insight

There are two Processor SDKs, and they serve different purposes:

Processor SDK Linux Processor SDK RTOS
Purpose Build Linux systems Baremetal / RTOS development
Relevant for you? Partially — U-Boot, toolchain, device trees Yes — CSL, PDK drivers, board init
Size ~1.8 GB installer ~1.8 GB installer
Host Linux x86_64 only Linux + Windows
Key output SD card image with Linux + U-Boot Standalone binaries, SYS/BIOS apps
For your baremetal OS (JX): The RTOS SDK's PDK is the most directly useful — it provides the register-level headers and driver source code. The Linux SDK is useful as a reference for U-Boot source, device trees, and the create-sdcard.sh script.

SDK Components — A Map

Both SDKs share a similar structure. Here are the directories you'll care about:

processor-sdk-rtos-am57xx/
├── pkg/                          # ← THIS IS THE MAIN SDK
│   ├── ti/
│   │   ├── csl/                  # Chip Support Library (register headers)
│   │   │   └── csl_uart.h,
│   │   │       csl_gpio.h, etc.  # Direct register access macros
│   │   ├── board/                # Board init (pinmux, clock, DDR)
│   │   │   └── src/am57xx_evm/   # ← Reference for writing BBAI board file
│   │   ├── drv/                  # LLD — peripheral driver libraries
│   │   │   ├── uart/             # UART low-level driver
│   │   │   ├── i2c/              # I2C low-level driver
│   │   │   └── gpio/             # GPIO low-level driver
│   │   ├── osal/                 # OS Abstraction Layer
│   │   └── starterware/          # Simple baremetal examples
│   └── docs/                     # API documentation
├── makerules/                    # Build system rules
└── examples/                     # Example projects
Cheat sheet: CSL = raw register access (what you're already doing in main.c). LLD = wrapper functions. Board = pinmux + clock + DDR init. For your baremetal OS, you want CSL headers and board init as reference.

The SoC vs. Board Problem

This is the most important concept in this lesson. TI ships support for their SoC (AM5729) but not for every board that uses it.

TI providesYou must write
  • CSL headers for AM5729 registers
  • PDK driver source (UART, GPIO, etc.)
  • AM5729 TRM (7000 pages)
  • EVM + IDK board files as reference
  • U-Boot SPL + board code
  • BBAI board init (board.c)
  • Pinmux table (which pins are UART, GPIO, etc.)
  • DDR3L timing config for BBAI's specific RAM chips
  • Clock tree init for the 20 MHz reference oscillator
This is why we extracted MLO and u-boot.img from a pre-built Debian package instead of building them. The pre-built images include the board-specific BBAI init — building from source requires writing the BBAI board file first.

The SD Card Tool You Already Used

The Linux SDK includes create-sdcard.sh, which automates exactly what we did manually:

# Inside the Linux SDK after install:
./bin/create-sdcard.sh

# It does:
# 1. Partition SD card (FAT32 boot + ext4 rootfs)
# 2. Write MLO to sector 512
# 3. Copy u-boot.img to FAT partition
# 4. Copy kernel, device tree, rootfs

We replicated this manually using dd, mformat, and mcopy. Understanding the manual process (as we did) is more valuable than running the script — now you know why each step exists.

Key Takeaway

The TI Processor SDK is not a single tool. It's two SDKs (Linux + RTOS), each containing many independently useful components. For baremetal work, the RTOS SDK's PDK is the treasure — but you'll need to write the BBAI board-specific code yourself, using the TI EVM board files as reference and the TRM as your final authority.
