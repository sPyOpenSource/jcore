Machine Learning on an RTOS

What runs, what doesn't, and what the BBAI's hardware can do

The Short Answer

You cannot train models on an RTOS (no PyTorch, no GPU drivers, no Python). You can run inference — deploy a pre-trained model to make predictions — on an RTOS, as long as the model is simple enough and you have the math routines.

Inference on an RTOS: How It Works

You train on a server, export the model (weights + architecture), cross-compile an inference engine, and link it into your RTOS image. The RTOS never sees Python or PyTorch — it only runs the compiled forward pass.

Training (x86 Linux):
  train.py  →  model.pt  →  export → model.onnx / model.tflite

Cross-compile (macOS → ARM):
  model.tflite  →  TFLite Micro for ARM  →  libtflm.a

Deploy (BBAI RTOS):
  kernel.bin + libtflm.a + model_data.o  →  linker → jx-rtos.elf

The BBAI's ML Hardware

The AM5729 has hardware for ML inference — and you're not using it:

AcceleratorCoresCould runReachable from your RTOS?
C66x DSP2Fixed-point matrix multiply, FIR filtersYes — TI's DSP linker, custom firmware
IVA-HD (video accelerator)1H.264 encode/decode, image scalingMaybe — register-level programming
PRU-ICSS2Real-time I/O, not ML**Yes — but wrong tool for ML
NEON SIMD (A15)1 per core32× faster matrix multiply vs scalarYes — inline assembly in your RTOS
Reality check: TI's ML stack (TIDL, EdgeAI) requires Linux + OpenCL + DSP firmware blobs. On a baremetal RTOS, you'd need to:
  • Write the DSP boot firmware yourself
  • Implement the RPMsg protocol for A15↔DSP communication
  • Hand-code matrix multiply on C66x in assembly
This is a large project on its own. For learning, start with NEON on the A15 — you can do useful ML inference without leaving your RTOS.

What You Could Actually Run on Your RTOS

// A tiny 2-layer MLP for MNIST digit recognition
// ~100 lines of C, no libraries needed

typedef struct { float w[784][64]; float b[64]; } Layer1;
typedef struct { float w[64][10];  float b[10];  } Layer2;

float relu(float x) { return x > 0 ? x : 0; }

int predict(Layer1 *l1, Layer2 *l2, float img[784]) {
    float h[64] = {0};
    for (int i = 0; i < 64; i++) {
        for (int j = 0; j < 784; j++)
            h[i] += img[j] * l1->w[j][i];
        h[i] = relu(h[i] + l1->b[i]);
    }
    float out[10] = {0};
    for (int i = 0; i < 10; i++) {
        for (int j = 0; j < 64; j++)
            out[i] += h[j] * l2->w[j][i];
        out[i] += l2->b[i];
    }
    int best = 0;
    for (int i = 1; i < 10; i++)
        if (out[i] > out[best]) best = i;
    return best;
}

This runs in under 1 ms on a Cortex-A15 at 1.5 GHz. You can train the weights on your laptop with PyTorch, dump them as a C header, and link them into your RTOS. No DSP, no GPU, no Linux needed.

The Real Value: Sensor Fusion at Deadline

An RTOS + ML combination shines when you need to:

  1. Read a sensor at a fixed rate (e.g., IMU at 1 kHz)
  2. Run a tiny model on the sensor data (e.g., detect "tap" gesture)
  3. Produce an output before the next sample arrives (1 ms budget)

This is the killer app for RTOS ML — not running large models, but running small, fast, deterministic models on streaming sensor data where a late answer is wrong even if numerically correct.

Quiz

Q1: Can you train a neural network on an RTOS?

Answer: No. Training needs Python, GPU, GB of memory. You train on a server and deploy the weights to the RTOS.

Q2: Your BBAI RTOS needs to classify audio samples at 10 kHz. Which hardware do you use?

Answer: Start on the A15 with NEON SIMD. If it fits in 100 µs per sample, you're done. If not, move to the C66x DSP — but that means writing DSP firmware separately.

Q3: What's the point of running ML on an RTOS instead of Linux?

Answer: Deterministic timing — the inference completes within a known bound every time. On Linux, a context switch could delay inference by milliseconds.
