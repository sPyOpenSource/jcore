Lesson 1: The Big Picture

Porting a codebase from x86-32 (IA-32) to x86-64 (AMD64/Intel 64) is more than just flipping a compiler switch. While the instructions are largely compatible, the underlying architectural model changes significantly.

Key Concept: The transition from 32-bit to 64-bit primarily affects how the CPU handles memory addresses and how it stores temporary data in registers.

1. Address Space Expansion

In x86-32, pointers are 32 bits wide, limiting the maximum addressable memory to 232 bytes, which is 4 GB. In x86-64, pointers are 64 bits wide, theoretically allowing up to 264 bytes (though current implementations usually limit this to 48 or 57 bits, still providing petabytes of space).

Impact: Any assumption in your code that a pointer fits into a 32-bit integer will cause crashes or data corruption on x86-64.

2. Register Expansion

The general-purpose registers have been widened from 32 bits to 64 bits. They also get new names:

  • EAX (32-bit) → RAX (64-bit)
  • EBX (32-bit) → RBX (64-bit)
  • ECX (32-bit) → RCX (64-bit)
  • EDX (32-bit) → RDX (64-bit)
  • ESI, EDI, EBP, ESP → RSI, RDI, RBP, RSP

Additionally, x86-64 introduces eight new general-purpose registers: R8 through R15.

3. Pointer Size Change

This is the most common source of bugs during porting. In x86-32, sizeof(void*) == 4. In x86-64, sizeof(void*) == 8.

If your code does something like this:

uint32_t address = (uint32_t)ptr;

It will truncate the address on a 64-bit system, leading to a segmentation fault.
