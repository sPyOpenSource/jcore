Glossary

Disabling Paging

Lesson 5 of the x86 Processor Modes series.

1. Why Disable Paging?

Once paging is on, it's usually on for good — but there are specific reasons to turn it off:

  • Switch to real mode: real mode has no paging. To call BIOS interrupts, you must disable the MMU entirely (JCore's prot_to_real does this).
  • Change the paging mode: to switch from 32-bit paging to 4-level (long mode) paging, you must disable paging first, then re-enable with new page tables.
  • Early boot: some kernels identity-map first, enable paging, then remap — requiring a brief paging-off window.
  • Transition from long mode → protected mode: you must clear CR0.PG, which drops you from long mode.
Warning: Disabling paging while the instruction pointer (EIP/RIP) is in a page that is not identity-mapped causes an immediate triple fault — the CPU resets.

2. The Triple Fault Trap

When you clear CR0.PG, the MMU stops translating. The CPU immediately starts treating every address as a physical address. If EIP points to virtual address 0xC0100000 but the CPU now fetches from physical address 0xC0100000 (which has no code or RAM mapped), it raises a page fault (#PF). The page fault handler can't run (no IDT in real mode), which causes a double fault. The double fault handler also can't run → triple fault → CPU reset.

The fix: the instruction that clears CR0.PG, and every instruction after it up to the far jump, must be in an identity-mapped page (virtual = physical).

3. Disabling Paging in Protected Mode

This is what JCore does in asm.S:prot_to_real. The relevant part before the actual mode switch:

prot_to_real:
    ; save protected mode stack
    movl    %esp, %eax
    movl    %eax, protstack

    ; get return address
    movl    (%esp), %eax
    movl    %eax, STACKOFF

    ; switch to 16-bit data segment (still protected mode)
    movw    $KERNEL_16_DS, %ax
    movw    %ax, %ds
    ; ... other segments ...

    ; far jump to 16-bit code segment
    ljmp    $KERNEL_16_CS, $tmpcseg

tmpcseg:
    .code16
    ; NOW clear CR0.PE — exit protected mode entirely
    movl    %cr0, %eax
    andl    $CR0_PE_OFF, %eax   ; clear PE bit
    movl    %eax, %cr0

    ; far jump to real mode code segment
    DATA32  ljmp    $0, $realcseg

Note: JCore doesn't explicitly clear CR0.PG here because it doesn't use paging — it runs with segmentation only. If paging were on, the sequence would be:

; Step 1: Identity-map the current code page
; (already done if the kernel is identity-mapped)

; Step 2: Clear CR0.PG
movl    %cr0, %eax
andl    $0x7FFFFFFF, %eax     ; clear PG (bit 31)
movl    %eax, %cr0

; Step 3: Immediate far jump — must be in identity-mapped page!
jmp     $KERNEL_CS, $paging_off
paging_off:
; MMU is now off. All addresses are physical.

4. Disabling Paging from Long Mode

Long mode makes this harder — you can't clear CR0.PG while in 64-bit mode. You must first drop to compatibility mode (32-bit long mode sub-mode):

Sequence: Long Mode → Compatibility Mode → Paging Off → Protected Mode

1. Far jump to a 32-bit CS (GDT entry with L=0, D=1)
   → CPU is now in compatibility mode (still in long mode,
      but running 32-bit code)

2. Clear CR0.PG (instruction must be identity-mapped)
   → EFER.LMA is cleared automatically
   → MMU off, CPU falls back to legacy protected mode

3. Clear EFER.LME to fully exit IA-32e mode
   (optional — only needed if re-entering long mode later)

4. From here, continue to prot_to_real if needed

The far jump in step 1 is the critical piece: load CS with a descriptor whose D=1 (32-bit default) and L=0 (not 64-bit). This keeps the CPU in long mode, but running 32-bit code. Then CR0.PG can be cleared.

5. TLB After Disabling Paging

When CR0.PG is cleared, the TLB is not automatically flushed on all implementations. The Intel manual recommends:

; After clearing CR0.PG:
mov    %cr3, %eax   ; read CR3
mov    %eax, %cr3   ; write it back → flushes TLB

A CR3 reload (even writing the same value) invalidates all non-global TLB entries. This is essential before re-enabling paging with a different page table structure.

6. The Identity Mapping Requirement

Every instruction that touches CR0.PG (and any instruction fetched while the MMU is in transition) must be at a virtual address that equals its physical address. This is called identity mapping (or 1:1 mapping).

There are two strategies for this:

  • Permanent identity map: keep the first 4 MB identity-mapped at all times (wastes TLB entries but is simple).
  • Trampoline code: copy a small routine to an identity-mapped page before disabling paging, jump to it, execute the CR0.PG clear, then proceed. Linux uses this for SMP startup (trampoline.S).

JCore uses approach 2 implicitly: its kernel is loaded by GRUB at physical 2 MB and linked at virtual 2 MB (see linker.ld: . = 2M), so the kernel's virtual addresses ARE its physical addresses — it's identity-mapped by default.
